# Каталог правил

`cash_checks.json` — каталог, по которому работает сервис. В нём 13 правил, и у каждого:

- тип нарушения;
- документ, пункт и ссылка на adilet.zan.kz;
- описание для проверяющего;
- ровно один предикат `required` — что должно быть видно на записи.

Тексты норм сверены с действующими редакциями на adilet.zan.kz 18.10.2026. Цитаты и разбор по каждому правилу — в [docs/sources.md](../docs/sources.md); цитаты для интерфейса — в `frontend/dist/norms.js`.

Результат — признак возможного нарушения для проверки человеком, а не юридическое заключение.

## Как каталог используется

- **Анализатор** (`vision/src/forte_vision/anchored/`) читает каталоги из `FORTE_RULE_CATALOGS` (по умолчанию `["rules/cash_checks.json"]`). Он выдаёт предикат, только если тот есть в каталоге (`decide.PREDICATE` → `required`). Нет правила в каталоге — нет и проверки.
- **Движок правил** (`decision/forte_decision/backend_adapter.py`) превращает наблюдение `{предикат: observed}` в нарушение с типом и описанием.
- **Worker** дописывает к описанию строку «Нормативное основание: документ — тип; пункт (ID: rule_id). URL». Интерфейс по `rule_id` показывает дословную цитату из `norms.js`.
- **Поля `rule_id`, `type`, `title`, `required`** читают анализатор, оценщик `data_tools/score_videos.py` и тесты. Их меняют только вместе с кодом и замером.

## Правила

«Прямо» — пункт содержит требование. «По смыслу» — прямого требования нет, применение — трактовка команды; так написано и в поле пункта, и в описании.

У трёх правил id начинается с `TEAM_`: они появились до того, как нашлась опора в актах. Id не переименованы, потому что их читает код. Тест `test_rules_without_a_direct_norm_say_so` требует, чтобы у таких правил в поле пункта было написано «нет … трактовка».

DOC, AUTH и REG в каталоге оставлены, но схема «по якорям» их не проверяет, и в ответах сервиса их нет. Правила KEYS («ключи в замке сейфа», п. 80) в каталоге нет: проверку никто не измерял.

## Ограничения

- По видео не устанавливаются учёт, регистрация суммы, проводки и сверка. Формулировки — «в кадре не видно», а не «не сделано».
- Телефон не помечается: п. 12 ч. 2 допускает средства связи без фото- и видеофиксации, а по видео это не определить.
- Право посетителя на внеочередное обслуживание по видео не определяется.
- Нормы Правил № 14, п. 16, действуют в редакции на период приостановления до 01.01.2027. После этой даты их нужно перепроверить.

## Другие файлы

- `cash_receipt.json` и `predicate_questions.json` — два первых правила по п. 20 и п. 22 с подробными предикатами видимости. Они остались от раннего движка; текущий анализатор их предикаты не выдаёт. Тесты: `test_catalog.py`.
- `test_checks_catalog.py` проверяет каталог: 13 правил, один предикат на правило, ссылка на adilet, «проверяет человек» в описании, срабатывание только своего предиката.

## Как добавить правило

1. Найти пункт в действующей редакции на adilet.zan.kz и скопировать цитату в `docs/sources.md` и `frontend/dist/norms.js`.
2. Записать в `source_paragraph` и в описании «по смыслу», если прямого требования нет.
3. Сформулировать предикат через видимое действие или состояние и подобрать контрпример без нарушения.
4. Добавить проверку в анализатор и измерить её на всех чистых роликах до включения в прод.
5. Соблюдать границы контракта backend: `source_paragraph` ≤ 200 символов, «документ — тип» ≤ 500, в документе нет «;» (по нему интерфейс разбирает основание).

Видео, кадры и их описания не отправлять облачным сервисам.
