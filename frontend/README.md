# Frontend

Статический интерфейс проверки видео. Backend раздаёт `dist/index.html` из `frontend/dist`, если папка указана в `FORTE_FRONTEND_DIST` (по умолчанию `./frontend/dist`). Сборщик и npm-зависимости не нужны.

Интерфейс оформлен как светлое рабочее место аналитика: слева находятся реальные разделы и список эпизодов, справа — загрузка или разбор результата. На телефонах разделы открываются выдвижным меню, а загрузка, доказательства и сведения складываются в одну колонку. Визуальная система использует спокойные нейтральные поверхности и индиго для главных действий.

## Контракт

- `POST /ui-api/analyze` с `multipart/form-data` и полем `file`.
- `GET /ui-api/jobs/{job_id}` с интервалом 1,5 секунды до терминального ответа.
- Типы wire-ответов, runtime-проверка и same-origin HTTP-клиент находятся в `dist/api.js` (JSDoc, без сборщика и внешних зависимостей).
- Раздел **API** (`dist/api-docs.js`): общий ключ жюри (`GET /ui-api/key`, всегда один и тот же) показывается сразу и подставляется в примеры; base URL текущего origin с копированием; быстрый старт на cURL / PowerShell / Python / JavaScript (загрузка → опрос; JavaScript-пример перенесён из 698cfc3); карточки `POST /api/v1/analyze` и `GET /api/v1/jobs/{job_id}` с полями, примерами ответов для каждого статуса и кодами ошибок; таблица полей результата; лимиты текстом; служебные маршруты. Python- и cURL-примеры прогнаны против живого сервиса, вход с общим ключом в `/api/v1` и неизменность ключа после перезагрузки проверены на локальном бэкенде.
- Статусы: `processing`, `failed`, `done`. UI никогда не показывает `failed` как отсутствие нарушений.
- Экран обработки: превью кадра и сведения о файле (размер, длительность, разрешение) читаются из выбранного файла в браузере; шаги «Загрузка → Анализ → Результат», таймер против лимита 5 минут. Процент есть только у загрузки — это фактический прогресс передачи (`uploadWithProgress` на XHR в `dist/api.js`); у анализа процента нет, полоса неопределённая. Временные сетевые ошибки отделены от `failed`, опрос можно продолжить по сохранённому `job_id` без повторной загрузки; сам `job_id` пользователю не показывается.
- Форма принимает MOV до 50 МБ (50 × 1024² байт), тот же лимит по умолчанию у backend (`FORTE_MAX_UPLOAD_MB=50`); больше — `413`. Самый крупный ролик открытого набора — 28,7 МБ.
- В итоговом ответе отображаются тип эпизода, таймкод, описание и 1–3 JPEG-кадра из `evidence_frames`.
- Свой плеер исходного видео (`dist/player.js`, файл открывается локально в браузере): на шкале — метки найденных эпизодов (клик выбирает эпизод и синхронизирует список и кадры) и тики кадров-доказательств выбранного эпизода; при наведении — превью кадра из второго декодера того же файла; плашка «Эпизод N» поверх видео рядом с таймкодом события; переключение эпизодов, покадровый шаг (1/30 с), скорость 0,25–2×, полный экран. Клавиши: пробел/K, ←/→ (Shift — 5 с), «,»/«.» — кадр, «[»/«]» — эпизод, F. Звука в кейсе нет, поэтому регулятора громкости нет. Если браузер не воспроизводит MOV, остаются JPEG-кадры доказательств.
- Runtime-клиент UI не вызывает `/api/v1` и не получает ключ жюри; API-страница содержит только копируемый пример с переменной `$env:FORTE_API_KEY`, без значения ключа. Рабочие запросы интерфейса идут на тот же origin; видео передаётся backend-сервису для анализа, а кадры возвращаются его API. Внешние AI-сервисы не используются.
- В карточке «Основание» — название нормы, пункт, дословная цитата пункта и источник (adilet.zan.kz). Цитаты лежат в `dist/norms.js` по `rule_id` каталога `rules/*.json`; каждая сверена дословно с adilet (помечена [A] в `case/norms/sources.md`). Правило без записи в `norms.js` показывается без цитаты — пересказывать норму туда нельзя; при добавлении правила в каталог добавить и цитату.
- Экран результата показывает ленту эпизодов, кадры и их таймкоды, наблюдаемое действие и нормативное основание, если оно пришло от backend.
- Раздел «Результаты» всегда в меню: история завершённых проверок этого браузера (IndexedDB, `dist/history-store.js`, до 50 записей) — превью кадра, имя, дата, размер, длительность и вердикт; запись открывает полный разбор, её можно удалить, историю — очистить. Хранится JSON-ответ сервиса и уменьшенный кадр-превью; само видео не сохраняется, поэтому у записи из истории нет плеера, только кадры доказательств. На сервер история не отправляется.
- Боковую панель на широком экране можно тянуть за правую кромку (256–440 px, стрелки на клавиатуре, двойной щелчок — сброс) и сворачивать до колонки иконок кнопкой в её шапке или Ctrl/⌘+B; ширина и состояние хранятся в `localStorage` браузера (`sidebar-layout.js`).
- На широком экране навигация и эпизоды стоят слева, кадры — в ряд, а сведения отделены тонкими линиями. На меньших экранах навигация переходит в доступное выдвижное меню, а основные области складываются в колонку.

В репозитории есть локальные адаптеры анализа и правил (`forte_vision.backend_adapter:create_analyzer` и `forte_decision.backend_adapter:create_rules`), но `.env.example` по умолчанию использует заглушки. Для реального анализа установите runtime и веса по инструкциям в [`docs/ml-integration.md`](../docs/ml-integration.md) и [`vision/README.md`](../vision/README.md), затем задайте эти фабрики в конфигурации backend. Без этого backend вернёт `failed`, а интерфейс покажет незавершённую проверку, не выдавая её за чистый результат. Docker-образ сейчас не включает ML-runtime; на Apple Silicon worker с MLX запускается нативно на Mac.

## Синтетическая интеграционная проверка

Проверку схем job-ответа, same-origin ограничений, readiness request/ответа и отмены frontend API-клиента можно запустить без пакетов:

```sh
node --experimental-default-type=module frontend/tests/api.test.mjs
```

`data_tools/test_service_integration.py` создаёт синтетический MOV, использует тестовый анализатор и прогоняет реальный worker, API и независимый HTTP-evaluator. Он проверяет положительный, отрицательный и незавершённый результаты, но не качество реальной модели. В production нет переключателя, который подменяет ответ сервиса fixture-результатом. Запуск и требования к FFmpeg/ffprobe описаны в [`docs/ml-integration.md`](../docs/ml-integration.md).

Независимый evaluator `data_tools/evaluate_service.py` обращается к внешнему контракту `/api/v1`, не загружает модели и не вызывает rule engine. Он считает video TP/FP/FN/TN, метрики локализации эпизодов на внутренних окнах ±1/±3/±5 секунд (это не официальный скоринг), ошибки исполнения и время. Точность типа и нормы считается только при наличии таких полей в локальной gold-разметке; импорт текущего XLSX содержит бинарную метку и одну временную отметку, поэтому эти показатели там не размечены.

Публичный адрес deployment в репозитории не задан. До подключения реального анализатора и предоставления HTTPS-адреса нельзя заявлять о проверке UI на production backend или демонстрировать настоящий результат модели.

Сценарий честной пятиминутной демонстрации и условия готовности backend: [`DEMO.md`](DEMO.md).
