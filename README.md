# Кассовая дисциплина по видео — ForteBank Datathon 26

Сервис принимает запись камеры кассы (`.mov`) и ищет на ней видимые признаки нарушения кассовой дисциплины.
Ответ: вердикт `violation` / `no_violation`, а для каждой находки — тип, таймкод, 1–3 настоящих кадра из файла,
описание того, что видно, и пункт нормативного акта РК со ссылкой на adilet.zan.kz. Все модели работают локально,
облачные AI-сервисы не используются; результат — подсказка проверяющему, а не юридическое заключение.

| | |
|---|---|
| Веб-интерфейс | https://kassa-ai.oqcrm.kz |
| API | `POST /api/v1/analyze` (поле `file`, `.mov` до 50 МБ) → `{"job_id"}`; `GET /api/v1/jobs/{job_id}` → `processing` / `done` / `failed` и результат по схеме раздела 10 ТЗ |
| Ключ | заголовок `X-API-Key`, передаётся жюри отдельно; без верного ключа — 401 |
| Срок | 300 с с момента загрузки, включая очередь; ролики, загруженные одновременно, делят это окно поровну |

```bash
KEY='<ключ>'; BASE=https://kassa-ai.oqcrm.kz
JOB=$(curl -fsS -H "X-API-Key: $KEY" -F "file=@video.mov" $BASE/api/v1/analyze | python3 -c 'import sys,json; print(json.load(sys.stdin)["job_id"])')
while R=$(curl -fsS -H "X-API-Key: $KEY" $BASE/api/v1/jobs/$JOB); echo "$R" | grep -q '"processing"'; do sleep 2; done; echo "$R"
```

## Как это работает

```
POST /api/v1/analyze ──► API (FastAPI): ключ · .mov · ≤50 МБ · дедлайн = приход + 300 с
                         └► очередь SQLite ──► worker: по одному; ролики залпа делят окно поровну
                                                 └► процесс модели (анализатор + правила)
1. Видео: ffprobe, реальные метки времени кадров (PTS); звук не читается.
2. Люди: RF-DETR nano (COCO) по всему ролику до 5 кадров/с. Кассир — тот, кто дольше всех сидит на одном месте;
   события: встала, ушла, вернулась, клиент пришёл/ушёл, смена клиентов, второй посетитель.
   Лица не распознаются и не сравниваются — только рамки «человек».
3. Зоны сцены: сейф, экран, стол, дверь, счётная машинка — Qwen3-VL находит их на кадре этого ролика
   (координаты обучающей камеры не используются).
4. Предметы на столе: что появилось и осталось лежать — по пикселям «до/после», люди закрашены.
5. Вопросы модели: увеличенные вырезки нужной зоны в моменты событий, ответ «да/нет» или выбор из списка
   (деньги / документы / мешок / сумка / еда / телефон / другое). Нарушение — только при подтверждении
   на двух разных кадрах; дверь — по пикселям створки.
6. Правила: каталог rules/cash_checks.json даёт тип, описание и норму; кадры-доказательства — кадры файла по PTS.
```

Если модель недоступна или не ответила на половину вопросов по событиям, задание завершается `failed`, а не
«нарушений нет». Видео удаляется сразу после обработки.

| Компонент | Что это | Лицензия |
|---|---|---|
| Qwen3-VL-8B-Instruct, GGUF Q4_K_M + mmproj Q8_0 | ответы по вырезкам, поиск зон | Apache-2.0 |
| llama.cpp `llama-server` | локальный сервер модели на GPU-машине | MIT |
| RF-DETR nano (COCO) | детектор людей | Apache-2.0 |
| FFmpeg / ffprobe | декодирование, кадры | LGPL/GPL (не AGPL) |
| FastAPI, SQLite, PyTorch | API, очередь, детектор | MIT / public domain / BSD |

## Типы нарушений, которые выдаёт сервис

| Тип (поле `type`) | Что проверяется на видео | Основание в каталоге |
|---|---|---|
| Дверь кассы не закрыта | дверь открыта и через 5, и через 8 с после входа кассира | НБРК № 14, п. 8, п. 16 пп. 1 |
| Сейф оставлен открытым | дверца сейфа открыта после ухода кассира или когда она села и продолжает работу | НБРК № 231, п. 20 пп. 2 |
| Уход с рабочего места с неубранными ценностями | после ухода на столе остались деньги или документы | НБРК № 231, п. 20 пп. 2 |
| Инкассаторский мешок не пересчитан и оставлен на столе | после ухода на столе мешок | НБРК № 231, п. 24 |
| Деньги предыдущего клиента не убраны или смешаны с деньгами следующего | при смене клиентов на столе деньги прошлого клиента | НБРК № 231, п. 20 пп. 2 |
| Пересчёт принятых денег после ухода клиента | клиент ушёл, а кассир продолжает считать | НБРК № 231, п. 20 пп. 1 |
| Личные вещи на рабочем месте кассира | на столе появилась сумка или одежда | НБРК № 231, п. 12 |
| Уход с рабочего места без блокировки компьютера | после ухода на экране открыт документ | прямой нормы нет — трактовка команды |
| Еда на рабочем месте кассира | на столе еда (напиток — не нарушение) | прямой нормы нет — трактовка команды |
| Обслуживание вне очереди | второй посетитель у стола, пока обслуживают первого | прямой нормы нет — трактовка команды |

Тексты норм, пункты и ссылки — `rules/cash_checks.json` и `rules/README.md`. Каталог содержит ещё правила
«приём без документа», «купюры не проверены на подлинность», «мешок в сейф без учёта» и «ключ в замке сейфа»:
их проверок в анализаторе нет, сервис эти типы не выдаёт.

## Ограничения и известные ошибки

- **Пропускает**: приём денег без документа клиента (Х-1, Х-2, Х-17), деньги не прогнаны через аппарат (Х-44),
  ключ оставлен в замке сейфа (Х-22: ключ — 3–5 пикселей), разговор с посторонним при выключенной технике (Х-30).
  Если детектор не нашёл ни одного события людей, вопросов к модели нет и вердикт — «чисто».
- **Ложные тревоги**: документы на столе после ухода кассира модель не отличает от рабочих бумаг (чистый Х-23).
- **Другой ракурс**: зоны ищутся заново на каждом ролике, сторона стола — по людям; если её определить нельзя,
  «обслуживание вне очереди» не утверждается. Дверь решается по пикселям и ошибается при движущейся камере
  (съёмка с рук 1280×720). ‹ЧИСЛА СИНТЕТИКИ›
- **Время**: один ролик 143 с — около 105 с. Пять роликов одновременно делят 300 с, каждому достаётся ~55 с,
  и разбор у поздних короче. 1080p: проверка файла 28 с вместо 6.
- Метки времени — по реальному кадру; для нарушений «по бездействию» таймкод — момент, когда шаг должен был
  произойти (уход кассира, смена клиентов).

## Требования ТЗ → как сделано → чем проверить

| Требование | Как сделано | Проверка |
|---|---|---|
| Загрузка, статус, вердикт в интерфейсе | веб-интерфейс, опрос статуса, два исхода | открыть сайт, загрузить `.mov` |
| Тип, таймкод, описание, 1–3 кадра, норма | `backend/worker.py` `_analyze_job`, каталог правил | ответ `GET /api/v1/jobs/{id}` |
| API по схеме раздела 10, `X-API-Key` | `backend/app.py`, `backend/contracts.py`; `queued` отдаётся как `processing` | `backend/tests` |
| 5 минут на видео | дедлайн от загрузки; дележ окна между роликами залпа | `backend/tests/test_fair_share.py`, `data_tools/burst_api.py` |
| Не утверждать по невидимым данным | проверки только видимых состояний; «учёт в системе» не проверяется | `vision/src/forte_vision/anchored/decide.py` |
| Локальность | модели на машинах команды, после загрузки весов интернет не нужен (`HF_HUB_OFFLINE=1`) | `infra/mac/mac.env.example` |
| Лица и звук | только рамки «человек»; декодируется один видеопоток (`-map 0:v:0 -an`, PyAV `streams.video[0]`) | `backend/video_io.py`, `vision/src/forte_vision/anchored/detect.py` |

## Запуск

Сервис: Mac на Apple Silicon (API, очередь, детектор), GPU-машина с `llama-server` (модель). В контуре банка —
один сервер с GPU: тот же `llama-server` на `127.0.0.1:8080` и сервис рядом.

```bash
git worktree add --detach ../deploy origin/main      # отдельная копия только для сервиса
cp infra/mac/mac.env.example ../local_data/mac.env   # пути, ключ жюри, FORTE_VLM_URL сервера модели
nohup ../deploy/infra/mac/serve.sh ../local_data/mac.env >/dev/null 2>&1 &
curl -i http://127.0.0.1:8000/health/ready           # 200 и "status":"ready"
```

`serve.sh` поднимает API (`uvicorn backend.app:app`), worker (`python -m backend.worker`), туннель до публичного
сервера и автодеплой `origin/main` по зелёным тестам; `touch $FORTE_DATA_DIR/DEPLOY_FREEZE` ставит деплой на паузу.
Модель: `llama-server -m Qwen3VL-8B-Instruct-Q4_K_M.gguf --mmproj mmproj-Qwen3VL-8B-Instruct-Q8_0.gguf -ngl 99 -c 8192
-fa on --parallel 1 --host 127.0.0.1 --port 8080 --api-key-file key.txt`. Подробности — `infra/mac/README.md`.

Тесты (как в автодеплое):

```bash
PYTHONPATH="$PWD:$PWD/decision:$PWD/vision/src" python -m pytest -q backend/tests decision/tests data_tools rules/test_catalog.py vision/tests
```

Замер на открытом наборе (нужны ролики организаторов в `../data/raw/open/videos`):

```bash
PYTHONPATH=.:decision:vision/src HF_HUB_OFFLINE=1 FORTE_VLM_URL=http://127.0.0.1:18080 FORTE_VLM_KEY_FILE=<ключ модели> \
FORTE_DETECTOR=nano FORTE_RULE_CATALOGS='["rules/cash_checks.json"]' \
python vision/tools/anchored_eval.py --factory forte_vision.anchored.analyzer:create_analyzer --videos all --out RUN
python -m data_tools.score_videos RUN
```

## Где что лежит

- `backend/` — API, очередь, worker, контракт ответа.
- `vision/src/forte_vision/anchored/` — анализатор: `detect.py` (люди), `people.py` (роли и события),
  `zones.py` (зоны), `desk.py` (предметы на столе), `ask.py` (вопросы модели), `decide.py` (проверки и таймкоды).
- `rules/` — каталог правил и норм; `decision/` — применение правил к наблюдениям.
- `frontend/dist/` — веб-интерфейс; `infra/` — запуск на Mac, ключ жюри, нагрузочные проверки.
- `vision/tools/anchored_eval.py`, `data_tools/score_videos.py`, `data_tools/burst_api.py` — замер, счёт, залп.
