# ForteBank Datathon — сервис анализа видео

Совместный проект локального анализа видео кассового обслуживания. Компоненты разрабатываются раздельно: локальное восприятие видео, проверка правил и оценка качества, backend, frontend. Готовность отдельного модуля не означает готовность всего сервиса.

Общие локальные данные можно хранить в игнорируемой директории `local_data/`. Видео, кадры, тестовые данные, API-ключи и веса моделей не размещаются в Git. После предварительной загрузки весов обработка выполняется внутри сервиса; видео, кадры и их описания не передаются внешним AI-сервисам.

Backend принимает видео, сохраняет задание в SQLite, передаёт его отдельному worker и выдаёт результат по контракту жюри. Модель и правила подключаются как локальные Python-плагины. Frontend разрабатывается отдельно в `frontend/`.

**В комплекте нет обученной модели и готового распознавания нарушений.** Адаптер по умолчанию завершает анализ со статусом `failed`. Ошибка, отсутствие ML и таймаут никогда не превращаются в `no_violation`. Для настоящего результата нужно подключить анализатор и правила команды.

## Запуск на Windows

Требуются Python 3.11+ и FFmpeg с `ffprobe`. Выполнять из корня репозитория. Данные и окружение хранятся локально и не попадают в Git.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c requirements.lock -e ".[dev]"
Copy-Item .env.example .env
# Сгенерировать значение для FORTE_API_KEY и сохранить его в .env:
.\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
ffmpeg -version
ffprobe -version
```

Если FFmpeg не в `PATH`, указать абсолютные пути к `ffmpeg.exe` и `ffprobe.exe` в `.env`. Дистрибутивы доступны через [страницу FFmpeg](https://ffmpeg.org/download.html). Значение `replace-with-a-long-random-secret` необходимо заменить.

Первый терминал:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Второй терминал, та же папка и `.env`:

```powershell
.\.venv\Scripts\python.exe -m backend.worker
```

## Запуск на macOS / Linux

На Mac с Apple Silicon запускать worker нативно: Linux-контейнер не предоставляет модели доступ к Metal. ML-команда самостоятельно устанавливает зависимости своего плагина, совместимые с устройством.

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -c requirements.lock -e '.[dev]'
cp .env.example .env
python -c 'import secrets; print(secrets.token_urlsafe(32))'
# Сохранить сгенерированное значение как FORTE_API_KEY в .env.
# Установить ffmpeg/ffprobe средствами своей ОС и проверить:
ffmpeg -version
ffprobe -version
python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

В другом терминале активировать то же окружение и выполнить `python -m backend.worker` из корня репозитория. На одном каталоге данных должен работать один worker: он владеет моделью, а HTTP-процесс её не загружает.

## Frontend: согласованные точки подключения

Backend: `http://localhost:8000`. Frontend dev server: `http://localhost:5173`, proxy `/ui-api` → `http://localhost:8000`.

| Действие | Публичный UI | Жюри |
|---|---|---|
| Загрузить видео | `POST /ui-api/analyze` | `POST /api/v1/analyze` |
| Получить результат | `GET /ui-api/jobs/{job_id}` | `GET /api/v1/jobs/{job_id}` |
| Заголовок авторизации | Не нужен | `X-API-Key` |

Загрузка — `multipart/form-data`, поле `file`. Ответ: `{"job_id":"..."}`. Опрос раз в 1–2 секунды до `done` или `failed`. Очередь и работа модели отображаются одинаково: `processing`. В production FastAPI может раздавать готовый `frontend/dist` на том же origin; сборку frontend нужно предоставить отдельно.

Ключ жюри остаётся на сервере. Не помещать его в `VITE_*`, JavaScript или публичные файлы. `/ui-api` намеренно доступен без ключа и использует ту же ограниченную очередь.

Полные схемы и интерфейс ML: [contracts/README.md](contracts/README.md), [backend/contracts.py](backend/contracts.py).

Результаты выполненных проверок и ограничения: [infra/VERIFICATION.md](infra/VERIFICATION.md).

## Проверка через curl

Ниже используется **то же** значение ключа, которое сохранено в серверном `.env`. Сам `curl` не читает `.env`. Подставить путь к своему локальному видео и `job_id` из ответа загрузки.

PowerShell:

```powershell
$env:FORTE_API_KEY = Read-Host "Ключ из .env"
curl.exe -fsS -H "X-API-Key: $env:FORTE_API_KEY" -F "file=@C:/path/example.mov" http://localhost:8000/api/v1/analyze
curl.exe -fsS -H "X-API-Key: $env:FORTE_API_KEY" http://localhost:8000/api/v1/jobs/JOB_ID
curl.exe -fsS http://localhost:8000/health/live
curl.exe -i http://localhost:8000/health/ready
```

Bash / zsh:

```bash
read -r FORTE_API_KEY
export FORTE_API_KEY
curl -fsS -H "X-API-Key: $FORTE_API_KEY" -F 'file=@./example.mov' http://localhost:8000/api/v1/analyze
curl -fsS -H "X-API-Key: $FORTE_API_KEY" http://localhost:8000/api/v1/jobs/JOB_ID
curl -fsS http://localhost:8000/health/live
curl -i http://localhost:8000/health/ready
```

Для UI-пути убрать `X-API-Key` и заменить `/api/v1` на `/ui-api`. `/health/live` проверяет работу HTTP-сервера; `/health/ready` отражает готовность компонентов. Ответ liveness сам по себе не подтверждает, что модель подключена.

## Подключение ML и нормативных правил

1. Реализовать фабрики и интерфейсы из [контракта](contracts/README.md). Анализатор получает `AnalysisContext` и общий `VideoIO`; правила получают его наблюдения. Отдельный декодер внутри ML не нужен.
2. Установить зависимости плагинов в окружение worker. Заранее скачать разрешённые веса и настроить их локальные пути в плагине. Не добавлять веса в Git.
3. Указать `FORTE_ANALYZER_FACTORY=your_package.module:create_analyzer` и `FORTE_RULES_FACTORY=your_package.module:create_rules` в `.env`.
4. Перезапустить worker и проверить `/health/ready`, затем провести реальный прогон. Для production задать `FORTE_ENVIRONMENT=production`: режим отказывается запускаться с адаптером разработки или тестовыми плагинами.

Фабрика модели запускается один раз в процессе модели внутри worker. При аварии или превышении срока worker может перезапустить этот процесс. Модель не должна загружаться на каждый HTTP-запрос.

`deadline_at` — абсолютное время Unix. Лимит по умолчанию 300 секунд отсчитывается с прихода HTTP-запроса и включает загрузку, очередь, декодирование, ML и подготовку кадров. Анализатор должен учитывать оставшееся время. Нельзя отмечать неполный проход как успешный. Backend также контролирует срок извне.

Все видео, кадры и описания обрабатываются локально. Не подключать внешние AI API, распознавание личности или анализ аудио. Backend извлекает настоящие JPEG-кадры, учитывая PTS и ориентацию; итоговый `image_base64` не содержит префикса `data:`.

## Настройки и хранение

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `FORTE_ENVIRONMENT` | `development` | Строгая конфигурация плагинов в `production` |
| `FORTE_API_KEY` | Задать самостоятельно | Ключ только для маршрутов жюри |
| `FORTE_DATA_DIR` | `./data` | Видео и SQLite WAL; общий путь API и worker |
| `FORTE_DEADLINE_SECONDS` | `300` | Общий срок задания; максимум 300 секунд |
| `FORTE_MAX_UPLOAD_MB` | `64` | Максимальный размер одного файла |
| `FORTE_MAX_PENDING_JOBS` | `5` | Ограничение активных заданий и очереди |
| `FORTE_PROFILE` | `standard` | Профиль, передаваемый ML |
| `FORTE_WORKER_POLL_SEC` | `0.2` | Интервал проверки очереди |
| `FORTE_MAX_ATTEMPTS` | `3` | Ограничение повторных попыток после аварий |
| `FORTE_FFMPEG_BIN` / `FORTE_FFPROBE_BIN` | `ffmpeg` / `ffprobe` | Пути к декодеру и инструменту метаданных |
| `FORTE_FRONTEND_DIST` | `./frontend/dist` | Каталог готового frontend |

Задание сохраняется перед постановкой в очередь. SQLite и файлы должны лежать на локальном диске, доступном обоим процессам. Видео получает сгенерированное имя. Исходное расширение или MIME не доказывают корректность видео: worker проверяет возможность декодирования. Повреждённый файл может пройти загрузку и затем получить `failed` при обработке.

Сервис сохраняет исходные загрузки и результаты в каталоге данных. Перед демонстрацией учитывать свободное место; удалять данные завершённых прогонов только при остановленных процессах и когда они больше не нужны. Не удалять SQLite WAL/SHM отдельно от базы.

## Linux: Docker Compose

Нужен Docker с Compose. Сначала создать `.env` и задать настоящий ключ:

```bash
cp .env.example .env
# Отредактировать .env и подключить реальные плагины при необходимости.
docker compose build
docker compose up -d
docker compose logs --tail=100 api worker
```

API доступен на `http://127.0.0.1:8000`. API и worker используют общий именованный том `jobs`; `docker compose down` сохраняет его. `docker compose down -v` удалит данные, поэтому для обычной остановки его не использовать.

Образ включает backend и FFmpeg. Пакет модели и его зависимости нужно добавить в собственный образ до production-запуска. Если код плагина находится в `backend/`, он включается в сборку, но дополнительные зависимости всё равно требуется установить. Веса подключать отдельным read-only mount и передавать локальный путь плагину. GPU-доступ NVIDIA на Linux требует отдельной настройки runtime; этот Compose её не предполагает. Mac Metal использовать при нативном запуске, описанном выше.

Каталог `frontend/dist` подключается с хоста. Сборка образа не создаёт frontend и не скачивает веса. Для публичного адреса нужен предоставленный командой сервер/домен и настройка HTTPS; сам запуск Compose публичный адрес не создаёт.

## Проверки и воспроизводимость

```bash
python -m pytest
```

Тесты используют синтетические видео и тестовые адаптеры; эти адаптеры не предназначены для production. Проверять оба verdict, несколько событий, base64 JPEG, настоящие PTS, неверный ключ, повреждённый MOV, перезапуск worker и срок с учётом очереди.

Перед финальной сдачей команда должна прогнать самый длинный ролик и пять одновременных загрузок **на машине с настоящей моделью**, измерив время от начала запроса до результата. Ограничение очереди в пять заданий не означает, что любое GPU успеет обработать пять роликов за 300 секунд. Результаты синтетических тестов не доказывают скорость ML.

Для этого есть [infra/smoke_load.py](infra/smoke_load.py), использующий только стандартную библиотеку Python. Он читает ключ только из переменной окружения `FORTE_API_KEY` — её можно задать как в примерах curl выше. Указывать адрес сервиса команды; по умолчанию используется локальный `http://127.0.0.1:8000`.

```bash
python infra/smoke_load.py --video /path/to/longest.mov --concurrency 1 --output data/longest-results.json
python infra/smoke_load.py --video /path/to/first.mov --video /path/to/second.mov --concurrency 5 --timeout 310 --output data/load-results.json
```

В PowerShell использовать `python infra/smoke_load.py --video C:/path/example.mov --concurrency 5` из активированного окружения или указать путь `.\.venv\Scripts\python.exe`. Скрипт запускает ровно `--concurrency` заданий одновременно; если путей меньше, повторяет их по кругу. Замер включает передачу файла, очередь, обработку и задержку опроса, поэтому это время, наблюдаемое клиентом. JSON содержит времена, статусы и количество нарушений, без кадров, описаний и ключа. Код выхода `0` означает, что все задания завершились `done` в пределах 300 секунд; для другого бюджета есть `--budget-seconds`. С дефолтным адаптером ожидается `failed` и код выхода `1` — это не реальная проверка ML.

Для работы без интернета заранее подготовить Python-пакеты, FFmpeg, веса и зависимости ML. Файл `requirements.lock` фиксирует версии базового backend и тестовых инструментов; установка выше использует его как constraints. Он не включает модель и зависимости сторонних ML-плагинов. Проверенное окружение Windows не означает, что сборка Docker или весь ML-стек уже проверены на macOS/Linux: их нужно прогнать на целевой машине. Python выбирает бинарные пакеты для текущей ОС и архитектуры при установке. После подключения ML сохранить версии совместно проверенного окружения через `python -m pip freeze > requirements-tested.txt`, предварительно убедившись, что список не содержит секретных URL пакетов.

Перед **каждым commit и push** посмотреть diff, получить свежие изменения репозитория и проверить пересечения. Влить чужую работу локально, разрешить конфликты и повторить затронутые проверки. Не делать force-push общей ветки. Полные правила — [AGENTS.md](AGENTS.md).
