# Локальная инвентаризация данных

Модуль читает байты файлов для SHA256 и имена файлов. Он не декодирует кадры, не обращается к моделям и не выполняет сетевых запросов.

Из корня репозитория:

```sh
python -m data_tools.inventory /path/to/videos --output local_data/inventory.json
```

Необязательный `--annotations /path/to/annotations.json` принимает массив записей вида `{"file":"sample.mov","label":1,"timestamp_sec":12.5}`. Имена — относительные пути внутри указанного каталога. Для отрицательной метки допускается `timestamp_sec: null`.

Для исходной разметки XLSX есть отдельный импорт без чтения кадров:

```sh
python -m pip install -r data_tools/requirements.txt
python -m data_tools.import_labels /path/open_labels.xlsx \
  --videos /path/videos --output-dir local_data
```

Каталог `--videos` должен содержать видео, имена которых указаны в таблице. Импорт сверяет все строки с файлами, отказывается от пропусков и дублированных строк, сохраняет исходный номер строки. Формат `1минута 8 секунда` превращается в 68 секунд. Для проверки границ времени добавьте `--metadata metadata.json`: массив объектов `file` (относительный путь) и `duration` (секунды). Неопознанные значения и формулы отклоняются.

Создаются `annotations.json`, заполненный `inventory.json`, `gold.json` для evaluator, `review_queue.json` для локальной разметки типов и `import_summary.json` с агрегатами. Типы не придумываются; `event_type` остаётся пустым до локальной разметки и проверки человеком. Никакие результаты не попадают в Git. При первом импорте предоставленного файла: 42/42 размечены, 22 положительные, 20 отрицательных, 40 уникальных содержимых, одна группа дублей с конфликтом временной отметки. Это проверка импорта, не качество модели.

Разные метки или временные отметки у одинакового содержимого отмечаются как конфликт для локальной проверки человеком. Они не превращаются автоматически в несколько событий. Исходные аннотации сохраняются. NFC-нормализация учитывает разные кодировки Unicode, но латинская `X` и кириллическая `Х` не заменяются друг на друга.

`scenario_group` остаётся `null`, `split` — `unassigned`: хеш выявляет точные дубли, но не определяет общую постановку или съёмку. После ручной группировки создайте записи `video_id`, `sha256`, `group_id`, `split` для валидатора `forte-evaluate validate-splits`. Сначала распределяйте целые группы, затем настраивайте модель. Дубли не должны попадать в разные части данных даже при разных именах файлов.

`annotation_complete: false` означает, что бинарная метка и одна отметка времени не гарантируют исчерпывающей разметки событий. Полноту размечает человек. Инвентаризация не проверяет точность таймкода по длительности: это делает общий декодер/backend при импорте разметки.

Держите созданные манифесты и данные в игнорируемом `local_data/`. Не публикуйте видео, разметку и содержимое тестового набора жюри в репозитории.
