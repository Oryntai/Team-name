# decision — движок правил

Локальный Python-пакет `forte_decision`: без моделей, чтения видео, HTTP-сервера, загрузок и облачных вызовов. Превращает наблюдения анализатора в нарушения по каталогу правил.

## В проде

Backend вызывает фабрику `FORTE_RULES_FACTORY=forte_decision.backend_adapter:create_rules`. Она без аргументов создаёт `BackendRules` и загружает каталоги из `FORTE_RULE_CATALOGS` (JSON-массив локальных путей); если переменная не задана — `rules/cash_checks.json` репозитория. Каталог проверяется при старте процесса модели. Для тестов: `BackendRules(catalog_paths=[...], mode="review", max_anchor_delta_sec=1.0)`.

`rules/cash_checks.json` — действующий каталог: 13 правил с пунктами актов РК и ссылками на adilet.zan.kz, разбор — [rules/README.md](../rules/README.md) и [docs/sources.md](../docs/sources.md). Анализатор «по якорям» выдаёт предикаты 10 из них. Результат — признак возможного нарушения для проверки человеком, а не юридическое заключение. `rules/cash_receipt.json` — ранний каталог под прежний анализатор, в проде не загружается.

`evaluate(observations: ObservationBatch, context: AnalysisContext) -> list[RuleEvent]` принимает канонический контракт `backend/contracts.py` напрямую и отвергает другие словари и форматы.

- **Описание** RuleEvent — дословный `description_template` правила плюс строка «Что видно: …», собранная из `note` событий (`_with_seen`). Документ, название, пункт, ссылка и `rule_id` идут отдельными полями, и backend добавляет строку «Нормативное основание: …» ровно один раз.
- **Слияние:** события одного правила с пересекающимися или соприкасающимися интервалами и главными моментами в пределах `max_anchor_delta_sec` (по умолчанию 1 с) сливаются в одно; кадров — до трёх, ближайших к главному моменту.
- **Неполный анализ:** неполный пакет или только неразрешённые кандидаты → backend `IncompleteAnalysis` → задание `failed`, а не «чисто». Полный пустой пакет → `[]`. Найденное нарушение возвращается, даже если другие кандидаты не разрешены.
- **Длительность** видео адаптер не выводит: её и PTS проверяют VideoIO и worker. ID доказательств строятся детерминированно из `job_id` и PTS.

## Общий механизм

Анализатор «по якорям» передаёт только подтверждённые события: один предикат в состоянии `observed`, без пообъектной видимости. Остальной механизм движка остаётся для других анализаторов и аудита:

- Значение каждого предиката — ровно `observed`, `not_observed` или `unclear`; отсутствующий ключ — `unclear`. Оценки вместо трёх состояний не принимаются.
- Поля правила: `rule_id`, `type`, `title`, `source_document`, `source_paragraph`, `source_url`, `applicability`, `required`, `exceptions`, `visibility_required`, `description_template`. Описание — проверенный человеком текст без подстановок.
- Режим `review` (по умолчанию): все `required` — `observed`, все исключения — `not_observed`. Явное `not_observed` у ключевого предиката или условия применимости, как и `observed` у исключения, отклоняет правило. Неизвестный ключевой предикат оставляет кандидата неразрешённым. Режим `strict` дополнительно требует `observed` у применимости и видимости.
- Видимость объекта (`clear`, `partial`, `unusable`) не заменяет именованные предикаты видимости; если все объекты `unusable`, кандидат остаётся неразрешённым — ни нарушения, ни «чисто».

## Автономный формат и CLI

Для офлайн-проверок есть свой JSON-формат `Observation` (`video_id`, `duration_sec`, `analysis_status`, `coverage_complete`, `candidates`) и результат `DecisionResult`. Это внутренний формат CLI и тестов, а не второй формат обмена с сервисом и не схема ответа жюри.

Из `decision/`:

```sh
python -m pip install -e '.[dev]'
python -m pytest -q
forte-decide --observation /local/observation.json --rules /local/catalog.json \
  --output /local/decision.json --max-anchor-delta-sec 1.0     # или python -m forte_decision.cli
python -m forte_decision.evaluation evaluate examples/predictions.json examples/annotations.json
python -m forte_decision.evaluation validate-splits manifest.json
```

- CLI пишет только внутренний результат, видео не открывает. Коды выхода: 0 — анализ полный, 1 — ошибка входа, настроек или ввода-вывода, 2 — неполный анализ (результат всё равно сохранён) или ошибка аргументов. Несколько каталогов объединяются; повтор `rule_id` и пустой каталог — ошибка.
- `evaluation.py` не импортирует движок: считает TP/FP/FN/TN по видео и совпадение событий по времени при допусках 1/3/5 с. Пропущенные и `failed` предсказания никогда не считаются за TN.
- `validate-splits` проверяет, что одно видео (sha256) и одна группа не попадают в разные части train/dev/test.
- `examples/` — синтетические примеры для формата, а не нормы.

Счёт качества сервиса на открытом наборе делает отдельный скрипт `data_tools/score_videos.py`; цифры — [docs/SUBMISSION.md](../docs/SUBMISSION.md), раздел 7.

Настоящие наблюдения, результаты, описания, кадры и видео остаются локально: не отправлять их в облачные сервисы и логи облачных агентов.
