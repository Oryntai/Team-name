# Проверка сервиса

Состояние на 18 октября 2026. Сервис работает по адресу https://kassa-ai.oqcrm.kz с анализатором «по якорям»: RF-DETR nano плюс Qwen3-VL-8B на `llama-server`. Описание — [docs/SUBMISSION.md](../docs/SUBMISSION.md).

## Автоматический набор

```sh
python -m pytest -q -p no:cacheprovider backend/tests decision/tests data_tools rules/test_catalog.py vision/tests
```

Этот же набор гоняет автодеплой (`infra/mac/serve.sh`) перед установкой нового коммита `main`: не прошёл — остаётся прошлая версия. На коде `main` после `cc24f05` (18.10.2026): **454 теста прошли**. Модели в тестах заменены заглушками, поэтому набор проверяет интеграцию, а не качество распознавания.

GitHub Actions (`.github/workflows/backend.yml`) на каждый push запускает часть набора на Ubuntu 24.04 с Python 3.12: `backend/tests decision/tests data_tools/test_inventory.py rules/test_catalog.py`. Тесты vision в CI не входят.

Что покрывают тесты backend:
- **API:** авторизация жюри, отдельные публичные UI-маршруты, сохранение до ответа, лимит очереди, лимит потокового тела без Content-Length, медленная загрузка, истечение срока, запрет development-конфигурации в production.
- **SQLite и worker:**
  - атомарное получение задания, защита от старой попытки, блокировка второго worker;
  - авария процесса, восстановление после принудительного завершения, зависание модели;
  - срок с учётом очереди, проверка срока после ожидания блокировки SQLite;
  - деление пятиминутного окна между роликами залпа (`fair_share_end`).
- **Результаты:** оба verdict на синтетических адаптерах, несколько событий, настоящие JPEG из синтетического исходника, повреждённый MOV, незавершённый анализ, отсутствие ML.
- **VideoIO:** VFR, ненулевой start_time, соответствие цвета кадра его PTS, поворот на 90°, неполный файл, запрет плейлиста под расширением MOV, синтетическое длинное видео.

## На настоящей модели

Цифры и условия замеров — в [docs/SUBMISSION.md](../docs/SUBMISSION.md) §7:
- качество на 40 уникальных роликах открытого набора (33/40 при константе 21/40; поймано 15/21, ложная тревога 1/19 — X-23), на отложенной части и на синтетической перспективе (29/40, одна ложная тревога) — §7.1;
- все 40 роликов через публичный API по одному (код `ff8a62e`): ответы совпали с замером, `failed` — 0, медиана 59 с, максимум 141 с — §7.1;
- залп 5 × 143 с: все `done` ≤ 300 с, последний — 271 с; залп из 8 разных роликов: 8/8 `done` ≤ 300 с, верно 7/8 — §7.4;
- HEVC, тег поворота, 1080p, 25 и 60 кадров/с дают тот же ответ, что оригинал — §7.1.

Самый длинный ролик открытого набора: 142,533 с, 4273 кадра, 464×848.

## Что не проверено

- Docker-образ ставит только backend и анализатор запустить не может. Прод работает нативно: процессы на Mac поднимает `infra/mac/serve.sh`, модель — на GPU-машине команды.
- Качество на настоящей камере под другим углом не измерено: есть только синтетическая перспектива (SUBMISSION §7.1, §7.3).
- Текущий код через публичный API на всех 40 роликах не перегонялся; через публичный API на нём проверены залпы и форматы.
