# Ключ API для жюри

Адрес сервиса: https://kassa-ai.oqcrm.kz. Маршруты жюри — `/api/v1/analyze` и `/api/v1/jobs/{job_id}`, ключ — в заголовке `X-API-Key`. Интерфейс сайта ходит через отдельные маршруты `/ui-api` и ключ жюри не получает.

`/api/v1` принимает два ключа:

| Ключ | Откуда | Когда работает |
|---|---|---|
| Общий ключ сайта `fk_…` | страница «API» сайта, `GET /ui-api/key` | пока `FORTE_PUBLIC_API_KEYS` не выключен (по умолчанию включён; на проде включён) |
| `FORTE_API_KEY` | окружение процесса API или файл `.env`, который не идёт в git | всегда, если задан |

Оба сравниваются через `hmac.compare_digest`. Один и тот же ключ даёт и загрузку, и опрос задания. Без верного ключа — 401.

## Общий ключ на сайте

На время датахона жюри берёт общий ключ со страницы **API**. `GET /ui-api/key` при первом запросе создаёт `fk_…` (`secrets.token_urlsafe(32)`), хранит его в таблице `public_api_key` и затем отдаёт то же значение — после перезагрузки страницы и после перезапуска сервиса. Страница сразу показывает ключ и подставляет его в примеры cURL / PowerShell / Python / JavaScript.

Этот ключ публичный: его видит любой, кто открыл сайт. После мероприятия:
- **выключить:** `FORTE_PUBLIC_API_KEYS=false` и перезапуск API — страница перестаёт показывать ключ, `/api/v1` его отклоняет, работает только `FORTE_API_KEY`;
- **сменить:** удалить строку из `public_api_key`, следующий запрос создаст новый ключ.

Тесты: `backend/tests/test_api.py`, `test_public_key_*`.

## Отдельный ключ `FORTE_API_KEY`

Ключ, который лежит в открытом репозитории, в JavaScript или на публичной странице, публичен для всех. Если нужен закрытый ключ для отдельной выдачи — его генерирует владелец сервиса и передаёт по закрытому каналу. Ключ один на всех, поэтому отозвать доступ одного проверяющего нельзя: только сменить ключ.

Из корня репозитория:

```sh
python infra/generate_jury_key.py            # создать .env из .env.example, если нужно, и записать ключ
python infra/generate_jury_key.py --rotate   # заменить ключ
python infra/generate_jury_key.py --show     # показать текущий ключ
```

Скрипт пишет 256-битный URL-safe ключ в `.env` и печатает его один раз. Повторный запуск без `--rotate` действующий ключ не заменяет. Вывод терминала — секрет: не запускать в логах CI, на скриншотах и трансляциях. После смены `.env` перезапустить API; старый ключ перестаёт работать. Значение из окружения процесса важнее `.env`, поэтому если `FORTE_API_KEY` задан в окружении (например, в env-файле `infra/mac/serve.sh`), менять нужно там.

## Вызов API

```sh
BASE=https://kassa-ai.oqcrm.kz
read -rs KEY   # вставить ключ со страницы «API»
curl -fsS -H "X-API-Key: $KEY" -F "file=@video.mov" "$BASE/api/v1/analyze"
curl -fsS -H "X-API-Key: $KEY" "$BASE/api/v1/jobs/JOB_ID"
```

Первый запрос возвращает `job_id`; второй опрашивать, пока `status` не станет `done` или `failed`. `failed` — не «нарушений нет». Схемы ответов — [`contracts/openapi.json`](../contracts/openapi.json), описание полей и кодов HTTP — [SUBMISSION.md](SUBMISSION.md), раздел 2.2.

Интерактивно: `https://kassa-ai.oqcrm.kz/docs` → **Authorize** → ключ. Swagger UI отправит его в `X-API-Key`.

## Ограничения

- `/ui-api` намеренно без ключа. Ограничения частоты запросов по IP в коде нет; от перегрузки защищает только лимит очереди `FORTE_MAX_PENDING_JOBS` (при заполнении — 503 с `Retry-After: 5`). Есть ли ограничения на публичном сервере перед сервисом — не проверено.
- Общий ключ виден всем посетителям сайта; для закрытого доступа после мероприятия его нужно выключить, как описано выше.
