# Общий VideoIO для ML и доказательств

Реализация: `backend/video_io.py`. Worker передаёт уже созданный объект `video` в `analyzer.analyze(context, video)`. Используйте его для декодирования: отдельный `cv2.VideoCapture`, декодер VLM или вычисление времени через `frame_index / 30` приведут к расхождению с доказательствами.

## Публичный API

```python
VideoIO(
    path: pathlib.Path,
    *,
    ffmpeg_bin: str = "ffmpeg",
    ffprobe_bin: str = "ffprobe",
    deadline_at: float,  # абсолютные UTC Unix seconds, не длительность
)

video.probe() -> VideoMetadata
video.validate() -> VideoMetadata
video.frame_at(timestamp_sec: float) -> VideoFrame
video.frames_at(timestamps_sec: list[float]) -> list[VideoFrame]
video.iter_frames(interval_sec: float, batch_size: int = 256) -> Iterator[VideoFrame]
video.sample_frames(interval_sec: float, max_frames: int = 256) -> list[VideoFrame]
```

`VideoMetadata` — неизменяемый dataclass:

| Поле | Тип | Смысл |
|---|---|---|
| `duration_sec` | `float` | Длительность видео |
| `width`, `height` | `int` | Размер с учётом поворота на 90°/270° |
| `frame_pts` | `tuple[float, ...]` | Реальные времена всех декодированных кадров относительно начала видеопотока |
| `start_time_sec` | `float` | Исходный `start_time` потока; при его отсутствии — PTS первого кадра |
| `rotation_degrees` | `float` | Поворот из метаданных видео |

`VideoFrame` — неизменяемый dataclass с полями `timestamp_sec: float`, `jpeg_bytes: bytes`, `width: int`, `height: int`. JPEG содержит настоящий выбранный кадр с применённой ориентацией, без кропов, аннотаций и наложений. Это байты JPEG, **не** base64. Преобразование в base64 для внешнего ответа выполняет backend.

`probe()` получает метаданные и кадры через ffprobe, использует `best_effort_timestamp_time` / `pts_time`, вычитает `start_time` и проверяет порядок времён. `validate()` дополнительно декодирует весь первый видеопоток через FFmpeg и отклоняет повреждённые или неполные видео. Worker вызывает `validate()` до передачи управления анализатору. Метаданные и уже извлечённые кадры кешируются внутри объекта одного задания.

`frame_at(t)` выбирает ближайший настоящий кадр; при одинаковом расстоянии выбирается более ранний. Возвращённый `timestamp_sec` может отличаться от запрошенного `t`. Передавать в `frame_pts` наблюдений и правил нужно **возвращённое** время. Backend проверяет его принадлежность `metadata.frame_pts`. Время должно находиться в диапазоне `[0, duration_sec]` и быть конечным числом.

`frames_at(times)` выбирает ближайшие реальные кадры для не более 256 точек за один вызов FFmpeg, сохраняя порядок и повторы запроса. Используется тот же кеш исходных JPEG.

`iter_frames(interval_sec, batch_size=256)` проходит всю временную шкалу пакетами до 256 кадров. Для каждой точки равномерной сетки берётся первый реальный кадр на ней или после неё; пустые интервалы VFR схлопываются, повторов кадров нет. Интервал — конечное число не меньше 1e-6. Это пакетная выборка через общий декодер, а не отдельный потоковый декодер: новый пакет может повторно прочитать начало файла. Размер пакета ограничивает один запрос FFmpeg, но кеш JPEG накапливает все выбранные кадры; частоту выбирайте с учётом памяти и срока задания. Модель уменьшает изображения самостоятельно; оригиналы остаются в общем кеше для доказательств.

## Выборка и полнота анализа

`sample_frames(interval_sec, max_frames)` строит точки `0`, `interval_sec`, `2 * interval_sec`, …, выбирает ближайшие реальные кадры и убирает повторы. Интервал должен быть положительным конечным числом; `max_frames` — целое от 1 до 256. Выборка заканчивается у последнего PTS или после `max_frames` точек сетки, поэтому число возвращённых кадров может быть меньше лимита.

**Достижение лимита не означает, что просмотрен весь ролик.** Например, интервал 0,1 секунды с лимитом 256 покрывает лишь начало длинного видео. Анализатор должен выбрать интервал по длине записи, при необходимости отдельно запросить `video.frame_at(metadata.frame_pts[-1])` и выполнить требуемый своей методикой анализ оставшейся части. Даже равномерное покрытие временной шкалы само по себе не доказывает отсутствие нарушений между выбранными кадрами.

```python
import io
from PIL import Image

metadata = video.probe()
frames = video.sample_frames(interval_sec=1.0, max_frames=256)
for frame in frames:
    with Image.open(io.BytesIO(frame.jpeg_bytes)) as image:
        rgb = image.convert("RGB")
        # Локальная модель анализирует rgb; время события — frame.timestamp_sec.
```

Этот пример показывает доступ к кадрам, а не полноценный анализатор. `ObservationBatch.complete=True` выставляется только после реального завершения необходимого анализа. При нехватке времени возвращайте `complete=False` или поднимайте исключение; backend завершит задание как `failed`.

## Срок и ошибки

Каждая операция проверяет исходный `deadline_at`; время декодирования входит в общий срок задания вместе с загрузкой, очередью и ML. Проверять этот же срок нужно и внутри модельного inference. Декодирование не анализирует аудио и не делает сетевых запросов.

- `VideoError(ValueError)` — файл отсутствует, имеет неподдерживаемую структуру, повреждён или не декодируется; сюда же относятся недоступные FFmpeg/ffprobe.
- `VideoDeadlineExceeded(TimeoutError)` — общий срок истёк во время работы с видео.
- `ValueError` — некорректные параметры запроса кадра или выборки.

Не заменяйте эти ошибки пустым успешным результатом. Для доказательств используйте кадры общего `VideoIO`; уменьшенные или размеченные изображения, подготовленные для модели, не подменяют исходные JPEG.
